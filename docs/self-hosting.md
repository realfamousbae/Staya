# Свой сервер Staya

Сервер Staya не видит координат и содержимого сообщений: только случайные ID аккаунтов, публичные ключи, зашифрованные конверты фиксированного размера и время (docs/threat-model.md). Свой сервер меняет только то, **кто** видит эти метаданные.

## Что нужно

- VPS с Linux (проверено на Ubuntu 24.04), 1 vCPU и 2 ГБ памяти хватает с запасом; ~2 ГБ диска плюс карта региона (Москва с областью — ~600 МБ).
- Имя для TLS. Подойдёт бесплатное `<ip-через-дефисы>.sslip.io` или свой домен.
- Открытые порты 22, 80, 443/tcp.
- Docker с Compose на сервере; на своём компьютере — `ssh`, `rsync`, `openssl`.

## Установка

1. Пользователь для деплоя с входом по SSH-ключу и `sudo` без пароля. Вход под root по паролю `deploy/setup-server.sh` не трогает.
2. С компьютера, из корня репозитория:

   ```bash
   STAYA_HOST=user@host STAYA_DOMAIN=имя.сервера deploy/deploy.sh
   ```

   Скрипт настроит сервер (ufw, автообновления, Docker), сгенерирует **на сервере** пароль базы и код приглашения на регистрацию, скопирует `docker-compose.yml` и `Caddyfile` и запустит сервисы: Caddy (TLS от Let's Encrypt), сервер Staya, PostgreSQL, тайлы карты.
3. Боевой центр сертификации Let's Encrypt включается строкой `ACME_CA=https://acme-v02.api.letsencrypt.org/directory` в `/srv/staya/.env` на сервере (по умолчанию — тестовый).
4. Карта своего региона: поменять `BBOX` в `deploy/map/update-map.sh` и выполнить

   ```bash
   STAYA_HOST=user@host STAYA_DOMAIN=имя.сервера deploy/update-map.sh
   ```

5. Закрепление ключа: `deploy/backup-key.sh` (запасной ключ — в менеджер паролей), `STAYA_DOMAIN=имя.сервера deploy/pin.sh` (основной). Оба отпечатка — в приглашения (`docs/server.md`, «Закрепление ключа»).

## Регистрация

Код приглашения лежит на сервере в `/srv/staya/server.env` (`STAYA_INVITE_CODE`, права 600); его вводят при первом запуске приложения. Без кода регистрация открыта для всех — тогда уберите строку из `server.env`.

## Приватность

- Журналов запросов нет ни у Caddy, ни у сервера; IP клиентов используются только в памяти для лимитов частоты.
- Журнал PostgreSQL настроен так, чтобы не писать значения ключей.
- Резервные копии базы не нужны: при её потере клиенты перерегистрируются и заново публикуют ключи; теряются только недоставленные сообщения.
