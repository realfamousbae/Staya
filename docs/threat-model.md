# Модель угроз Staya

Статус: **v0.1** (задача 2.1), соответствует `docs/protocol.md` v0.1.

## 1. Что защищаем

| Актив | Где живёт |
| --- | --- |
| Координаты пользователя | Только в памяти и зашифрованной базе устройств его друзей |
| Приватные ключи | Только на устройстве, в зашифрованной базе; ключ базы — в Keychain / Android Keystore |
| Круг друзей | Устройства участников; сервер видит пары ID (см. метаданные) |
| Профиль (ник, аватар) | Только у друзей, передаётся через E2E |

## 2. Исходное допущение

**Сервер может быть взломан или изъят.** Даже с полным доступом к базе, логам и трафику атакующий не должен узнать, где находятся пользователи.

## 3. Противники и защита

| Противник | Возможности | Защита |
| --- | --- | --- |
| Чужой или self-hosted сервер (protocol §5.3) | Тот, кто держит сервер, к которому приглашение привело друзей | То же, что для любого сервера: координаты, профиль и настройки ему недоступны, он видит метаданные (§4). Подмена сервера по дороге (DNS, перехват) — отпечаток ключа TLS в приглашении (`p`), иначе запоминание ключа при первом подключении |
| Владелец или взломщик сервера | Читает базу, логи, трафик, может подменять, задерживать и повторять ответы | Сквозное шифрование; на сервере только шифротекст последнего пакета с TTL. Ключи друзей передаются вне сервера (QR) или сверяются кодом безопасности. Подпись одноразовых ключей проверяется ключом из QR. Отправитель определяется по сессии, которая расшифровала пакет, а не по полю сервера. Повтор старых пакетов и откат к старой сессии отсекаются самими сессиями: `advance_to(index + 1)` и удаление старых сессий после перехода на новую (protocol §7.5). Задержку и удаление пакетов сервер сделать может — это отказ в обслуживании, не утечка |
| Сетевой наблюдатель | Видит и изменяет трафик | TLS 1.3 + certificate pinning поверх E2E |
| Вор телефона (заблокирован) | Физический доступ | Ключ базы в Keychain / Keystore; база зашифрована; бэкап и перенос данных отключены |
| Вор телефона (разблокирован) | Открывает приложение | В MVP не закрыто; биометрическая блокировка — этап 5 |
| Бывший друг | Имел доступ раньше | Удаление уничтожает его Megolm-сессию и наш слот в его ящике; прямая секретность (`advance_to`) не даёт перечитать старые пакеты |
| MITM при добавлении | Подменяет ключи в канале связи | QR при встрече; для ссылок — код безопасности, статус «не проверено» до сверки |
| Провайдеры карт | Видят запросы тайлов | Тайлы, стиль, шрифты и спрайты только со своего сервера (3.9). Наш сервер видит, какие участки карты запрашивает клиент — примерно, где он смотрит, — но не пишет журнал запросов; тайлы кэшируются на устройстве. Запросы карты в приложениях — только https к привязанному серверу и с той же проверкой ключа TLS, что у API (4.4); журналы MapLibre выключены (адреса тайлов выдают место) |
| Apple / Google через пуши | Видят содержимое и время пушей | В MVP пушей нет; позже — только пустые пуши-сигналы |
| Цепочка поставок | Вредоносная зависимость или Action | Минимум зависимостей с обоснованием, `cargo deny`, Actions по SHA, никаких SDK аналитики и рекламы, позже — воспроизводимые сборки |

## 4. Метаданные, которые сервер видит в MVP

Осознанно принятые утечки:

- ID отправителя и получателя каждого пакета → граф дружбы. Снизит sealed sender (этап 5).
- Время отправки и ритм (чаще в движении, реже в покое) → примерная активность. Снизил бы постоянный фоновый трафик (cover traffic) — «Позже».
- Тип конверта (управляющий или позиция) и корзина размера управляющего сообщения (≤256 Б, ≤1 КБ, ≤9 КБ — например, видно, что отправлен аватар).
- Индекс сообщения Megolm в открытом виде → сколько пакетов отправлено другу с последней ротации и моменты ротаций.
- Заголовок Olm (ключ ratchet, счётчик) в открытом виде → сколько управляющих сообщений было между парой.
- Curve25519 `ik` отправителя в PreKey-сообщениях Olm (сервер и так знает его по регистрации).
- IP-адрес клиента при соединении. Сервер НЕ пишет IP в логи и хранит его только в памяти для rate limiting; Caddy access-логи выключены.

Не видит: координаты, режим для конкретного друга (точно / примерно / скрыто — все в одной отправке, пакеты одного размера), ник, аватар, настройки точности.

Глобальный призрак и заморозка шлют пакеты с частотой покоя, поэтому для сервера выглядят как «стоит на месте» — это часть уже принятой утечки ритма.

## 5. Ограничения примерной точности

`Approx` привязывает позицию к фиксированной сетке (~1 км) без шума. Друг с доступом `Approx` видит только ячейку, но замечает момент пересечения границы ячейки. Случайный шум хуже: его можно усреднить по многим пакетам.

## 6. Вне рамок

- Взломанная ОС, root или jailbreak на устройстве, вредоносная клавиатура или аксессибилити-сервис.
- Физическое принуждение разблокировать телефон.
- Определение местоположения оператором связи, Wi-Fi-сетями или самой ОС (Apple / Google location services).
- Друг, который сознательно пересылает твою позицию третьим лицам.

## 7. Открытые вопросы

- Биометрическая блокировка приложения и защита от просмотра на разблокированном телефоне (этап 5).
- Защита от перебора ID аккаунтов и спама запросами дружбы (частично — rate limiting и код приглашения на сервер в бете).
- Нужен ли cover traffic, чтобы скрыть ритм движения.
