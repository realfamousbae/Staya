# Сервер Staya

Актуальная установка на новом VPS описана в [self-hosting.md](self-hosting.md).

Общий Caddy размещается отдельно в `/srv/proxy`, приложение — в `/srv/staya`.
Первоначальная подготовка запускается через `deploy/bootstrap.sh`, дальнейшие
обновления — через `deploy/deploy.sh` с фиксированным `SERVER_TAG`.
Скрипт обновления не меняет настройки хоста и не перезапускает соседние проекты.

Прежний VPS и его TLS-ключи автоматически не мигрируются. Принудительные настройки
MTU старого провайдера больше не применяются к новым серверам.

API хранит только публичные ключи и зашифрованные конверты. Серверные миграции
применяются при старте под advisory lock; более новая схема блокирует запуск
старого бинарника. HTTP `/health` проходит к API и проверяет базу.

PostgreSQL доступен только во внутренней сети; API и тайлы — через loopback.
Caddy дописывает X-Forwarded-For; STAYA_TRUST_PROXY включён только за этим прокси.
IP используются для лимитов в памяти. Access-логов нет; журнал API содержит шаблон
маршрута, статус и длительность без координат, IP, тел и токенов. Лог PostgreSQL
исключает DETAIL и тексты запросов, чтобы не раскрывать идентификаторы.

Сохранять TLS-ключ Caddy: он закреплён в приложениях. `reuse_private_keys` оставляет
ключ при продлении. Запасной ключ хранить вне VPS; для его активации нужен выпуск
сертификата на этот ключ и явное подключение cert/key в Caddy. После ротации обновить
отпечатки в приглашениях. Смена IP/имени требует нового подключения к серверу.
