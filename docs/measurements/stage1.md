# Замеры этапа 1: фоновая геолокация и батарея

Задачи 1.4–1.5 в `docs/PLAN.md`. Результаты — в конце этого файла после замеров.

## Что меряем

Сколько раз и в каких условиях iOS/Android будят приложение в фоне и сколько это стоит батареи — для каждой стратегии. Приложение отправляет на сервер только метрики (`docs/server.md`), координат нет.

| Стратегия | iOS | Android |
| --- | --- | --- |
| S1 | только значимые изменения (SLC) | — (задача 1.3) |
| S2 | SLC + визиты | |
| S3 | SLC + непрерывные обновления, 100 м | |
| S4 | SLC + визиты, непрерывные только при движении | |

## Протокол для iPhone

**Перед серией** (4 стратегии × сутки почти упираются в 7 дней подписи AltStore):
1. Обновить приложение в AltStore (Refresh) прямо перед началом.
2. На экране «Staya · замер» проверить:
   - Геолокация — **всегда**, Точность — **точная**;
   - Фоновое обновление — **available**;
   - Энергосбережение — **выкл**;
   - Датчик движения (S4) — **разрешено** (если «не спрашивали», выбрать S4 при открытом экране).
3. Токен сборщика сохранён; «Тестовая отправка» → «Последний ответ: HTTP 204».

**Каждый день — одна стратегия:**
1. Выбрать стратегию, «Сбросить счётчики», включить «Запущено».
2. «Тестовая отправка» → HTTP 204 (проверка, что выбор применился).
3. Записать заряд и время начала. Дальше пользоваться телефоном как обычно: дом, дорога, город. Принудительно не закрывать приложение, кроме отдельного сценария ниже.
4. Через сутки: скриншот «Настройки → Аккумулятор» с долей Staya за 24 часа (основная метрика батареи — `battery_pct` в метриках меняется шагами ~5%) и скриншот экрана «Staya · замер».

**Отдельные сценарии** (по ходу любого дня, отметить время):
- принудительное закрытие свайпом — будит ли SLC приложение после этого;
- перезагрузка телефона;
- поездка на транспорте (для S3/S4).

## Протокол для Android

Стратегии (задача 1.3): **A1** — экономно, низкое потребление раз в 5 минут; **A2** — непрерывно, высокая точность каждые 100 м; **A3** — экономно в покое, непрерывно после датчика значимого движения, обратно через 10 минут без движения. Сервис переднего плана с постоянным уведомлением; без Google Play Services.

На Android сервис держит процесс живым, поэтому главный вопрос — **не убивает ли его производитель**. Для этого пульс `timer` раз в ~15 минут: пропуски пульса и метка `relaunched` — это и есть данные об остановках.

**Установка (S23 Ultra, Poco у друзей):**
1. APK собирать на Mac автора (`cd android && ./gradlew assembleDebug`): ключ отладки на Mac постоянный, поэтому обновления ставятся поверх без удаления (иначе пропадут токен, очередь и счётчики). Сборки из CI подписаны каждый раз новым ключом — для друзей не годятся.
2. Перед отправкой узнать архитектуру Poco: APK только для arm64-v8a. Если `adb shell getprop ro.product.cpu.abi` покажет `armeabi-v7a`, нужна отдельная сборка (`docs/PLAN.md`, «Проверить по ходу»).

**Перед серией** — на экране «Staya · замер»:
- Геолокация — **всегда** («Разрешить всегда»: без этого Android 14+ не поднимет сервис после перезагрузки или остановки системой), точность — **точная**;
- уведомление сервиса разрешено;
- «Оптимизация батареи» — **отключена для Staya**;
- **Xiaomi / Poco:** «Автозапуск» — вкл; «Контроль активности» — «Нет ограничений»;
- **Samsung:** «Батарея» — «Неограниченно»; добавить в «Приложения, которые никогда не спят»;
- токен сохранён; «Тестовая отправка» → HTTP 204.

**Каждый день — одна стратегия:** выбрать, «Сбросить счётчики», включить «Запущено», «Тестовая отправка» → 204, записать заряд и время. Через сутки — скриншот расхода батареи по приложениям (основная метрика батареи) и скриншот экрана замера.

**Отдельные сценарии:** смахнуть приложение из недавних; перезагрузить телефон (сервис должен подняться сам, событие `boot`); оставить телефон лежать на ночь (Doze, корзины App Standby).
